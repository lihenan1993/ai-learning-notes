# 为什么要用 Skills

## 1. Skill 是什么

Skill 是一个包含组织化文件的文件夹，用于扩展 AI Agent 的可复用能力。文件夹中可以放置：

- `SKILL.md`：技能名称、描述和执行规范。
- `references/`：供技能内部引用的资料文件夹。
- `scripts/`：需要执行的脚本。
- 模板、资源和其他辅助文件。

技能名称和描述用于帮助 Agent 发现合适的能力。技能可以引用同一文件夹中的其他技能或资源。

## 2. 为什么使用 Skill

使用 Skill 的核心目的是把可复用能力封装起来，减少重复编写提示词，并让 Agent 在需要时加载专业规则。

常见用途包括：

| 用途 | 示例 |
| --- | --- |
| 领域专业知识 | 品牌规范、法律审查流程、数据分析方法 |
| 可重复工作流 | 每周营销活动复盘、客户通话准备、季度业务复盘 |
| 新能力 | 创建演示文稿、生成 Excel 或 PDF 报告、构建 MCP Server |

## 3. 渐进式披露

Skill 遵循渐进式披露原则：

1. 上下文中先只保留技能名称和描述。
2. 当任务触发某个技能时，再加载它的 `SKILL.md` 内容。
3. 只有在必要时，继续读取 references、脚本或其他资源。

这样可以有意识地控制哪些信息进入上下文窗口，避免无关资料占用上下文。

## 4. 目录约定

- 技能目录使用小写字母和连字符，例如 `pdf-processing/`。
- 技能主文件通常命名为 `SKILL.md`。
- 内部引用资料放在 `references/`。
- 可执行脚本放在 `scripts/`。

## 5. 执行命令时的上下文控制

执行命令时，应明确命令输出哪些信息，并控制输出规模：

- 优先使用只返回必要字段的命令。
- 搜索时限定目录、文件类型和匹配范围。
- 对长输出使用摘要、分页或数量限制。
- 不把与当前任务无关的日志、依赖详情和大文件内容带入上下文。
- 需要进一步判断时，再执行更具体的命令获取细节。
