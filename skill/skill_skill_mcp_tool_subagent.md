# Skill、MCP、Tool 与 Subagent

## 1. 四者分别解决什么问题

| 组成 | 提供内容 | 持久性 | 加载或使用时机 | 最适合 |
| --- | --- | --- | --- | --- |
| Skill | 可复用的流程知识、指令、代码和资源 | 跨多个对话 | 按需动态加载 | 专业能力和重复工作流 |
| Prompt | 当前任务的自然语言指令 | 单次对话 | 每轮使用 | 快速请求 |
| Subagent | 独立处理任务的完整智能体逻辑 | 跨会话或由系统管理 | 被主 Agent 调用时 | 专门任务和任务委派 |
| MCP | 外部系统和数据的工具连接 | 持续连接 | 工具始终可用 | 数据访问和系统集成 |
| Tool | 更底层的系统访问能力及工具定义 | 当前上下文中始终存在 | Agent 需要执行操作时 | 读写文件、调用服务和执行命令 |

## 2. MCP：获取所需要的上下文

MCP（Model Context Protocol）将 Agent 与外部系统、数据源和服务连接起来。它可以提供查询数据、读取资源或执行操作所需的上下文，使 Agent 能在任务中访问外部能力。

Skill 可以使用 MCP 返回的数据和上下文。例如，一个数据分析 Skill 可以规定分析步骤，而 MCP 负责从数据库或业务系统获取原始数据。

## 3. Subagent：处理主线程和并行化任务

Subagent 拥有独立的上下文和工具权限。主 Agent 可以把明确的子任务委派给专门的 Subagent，由它独立处理并返回结果。

适合委派给 Subagent 的任务包括：

- 代码审查。
- 独立资料检索。
- 可并行执行的多个分析任务。
- 需要不同工具权限或专业上下文的工作。

Skill 可以向主 Agent 或 Subagent 提供领域知识、语言规范或框架最佳实践，但 Skill 本身不是独立执行任务的智能体。

## 4. Skill：处理可重复的工作流

Skill 用文件夹封装可复用能力，通常包含 `SKILL.md`、参考资料、脚本和资源。它适合保存稳定的流程知识和执行规范，并在任务触发时按需加载。

典型分工是：

1. Skill 规定应该怎样完成一类工作。
2. MCP 提供完成工作所需的外部数据和系统连接。
3. Tool 提供具体的底层访问能力。
4. Subagent 在需要时独立执行被委派的任务。

## 5. Tool：更底层的执行能力

Tool 是 Agent 用来访问系统并完成任务的底层能力，例如文件操作、命令执行、网络请求或服务调用。工具定义始终存在于上下文窗口中，Agent 可以根据任务选择调用合适的工具。

Skill、MCP 和 Subagent 都可能依赖 Tool：Skill 描述流程，MCP 暴露外部连接，Subagent 组织独立执行，而 Tool 最终完成具体操作。

## 6. 选择建议

| 需求 | 优先使用 |
| --- | --- |
| 保存可重复的专业流程 | Skill |
| 获取外部系统或数据 | MCP |
| 把工作拆给独立执行者 | Subagent |
| 直接读写系统或调用能力 | Tool |
| 只给当前轮次一个简单要求 | Prompt |
