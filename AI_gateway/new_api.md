# New API 大模型网关

> 本笔记基于 New API 官方文档整理。项目定位和功能会随版本演进；具体模型、接口、配置项以当前部署版本的文档和控制台为准。

## 1. New API 是什么

New API 是面向合法授权场景的 AI API 网关与用量管理系统，主要面向个人自用、团队内部管理和企业私有化部署。它把多个上游 AI 服务接入到统一平台，对下游应用提供兼容接口，并集中管理渠道、模型、用户、令牌、路由、用量和成本。

```text
业务应用 / AI 客户端
         |
         | 统一 API + New API Token
         v
      New API
         |
   渠道选择、模型映射、计量与日志
      /       |        \
模型供应商  云平台渠道  兼容接口/服务
```

官方项目介绍列出 OpenAI、Anthropic、Google Gemini、DeepSeek、Midjourney、Suno 等 30+ 模型服务。实际可用能力取决于部署版本、渠道配置、上游授权和服务商接口。

## 2. 定位与侧重

New API 的侧重点可以概括为：

> **统一模型 API + 渠道/模型管理 + 用户和令牌分发 + 用量计费与运营。**

它不仅是反向代理，也提供 Web 控制台，面向平台管理员与普通用户提供相应功能。与只在应用代码里集成模型 SDK 相比，业务侧可通过统一网关地址和令牌调用模型，渠道和模型的变化更多由平台侧管理。

主要用途：

- 团队统一接入获准使用的模型服务。
- 为用户、团队、项目或应用创建 API 密钥并控制模型权限和额度。
- 管理多个上游渠道，做优先级、权重分流和故障处理。
- 统计调用、Token、延迟、错误和费用，进行内部成本分摊。
- 通过游乐场、模型广场等控制台功能进行试用和运维。

## 3. 核心功能一览

| 功能域 | 主要能力 |
|---|---|
| 统一 API | 提供 OpenAI 兼容接口，并支持 Claude、Gemini 等相应格式/端点 |
| 渠道管理 | 配置上游供应商、Base URL、凭据、模型映射、渠道测试和多 Key |
| 模型管理 | 配置模型名称、可用状态、定价/倍率及可调用渠道 |
| 路由分流 | 多渠道负载均衡、优先级、加权随机、失败重试/切换及分组分流 |
| 用户与权限 | 用户角色、用户分组、管理员权限及账号安全管理 |
| API 密钥 | 创建令牌，设置额度、有效期、模型范围、分组、IP 白名单等限制 |
| 额度与计费 | 余额、配额、倍率、订阅、兑换码、成本核算及企业账务管理能力 |
| 日志与审计 | 查询调用日志、模型、状态、Token、耗时、错误和计费信息；管理员可查全站日志和操作记录 |
| 数据看板 | 分析调用量、模型使用、分流、用户、性能和成本等数据 |
| 游乐场与集成 | Web 控制台试用模型，提供 API/SDK 示例，并支持多种聊天应用配置导入 |
| 多模态与扩展 | 依版本/渠道支持 Responses、图像、音频、实时语音、Embedding、Rerank、视频或异步任务插件等 |
| 部署与运维 | Docker 等部署方式、系统设置、限流、性能监控、数据库和运行状态管理 |

## 4. 请求处理流程

```text
1. 客户端请求到达 New API
2. 校验 API Token、用户/分组、模型权限和限制
3. 将请求模型名映射到可用模型/渠道
4. 根据优先级、权重、分组等选择上游渠道
5. 转换或透传协议并调用上游
6. 按返回结果记录状态、耗时、Token 和费用
7. 将兼容格式的响应返回客户端
8. 若遇到可处理的上游错误，按配置重试或切换渠道
```

可用接口和转换路径依模型能力、渠道适配器与具体版本而异，不应假设任意接口在所有渠道都支持。

## 5. 渠道、模型与路由

### 5.1 渠道与模型的关系

- **渠道（Channel）**：一套连接上游服务的配置，通常包括供应商类型、密钥、Base URL、模型映射和附加参数。
- **模型（Model）**：下游请求使用的模型标识，以及平台侧的可用状态和计费配置。
- **分组（Group）**：把用户、令牌和可用渠道组织起来，可用于权限、倍率和路由隔离。

同一个逻辑模型可以配置在多个渠道上；平台通过路由配置选择实际上游。建议将业务使用的模型别名与上游部署名解耦，降低迁移供应商时对客户端的影响。

### 5.2 常见路由策略

- **优先级**：优先使用排序靠前的可用渠道；适合主备方案。
- **加权随机**：按渠道权重分配请求；适合按容量或目标比例分流。
- **多 Key 轮询/管理**：一个渠道或供应商配置多个密钥，分散请求或管理配额。
- **失败重试与自动切换**：渠道异常时尝试其他可用渠道；需结合错误类型和重试限制配置。
- **分组路由**：不同用户/令牌分组使用不同渠道、模型范围或费率。
- **模型映射**：对外模型名映射到上游实际模型或渠道支持的模型名。

路由策略与限制可能随版本变化。上线前用渠道测试和故障演练验证优先级、权重、限流、失败切换及计费结果。

## 6. API Token 与权限控制

New API Token 是下游调用网关的凭证，不等同于上游 Provider API Key。平台管理员配置上游渠道凭据；客户端只持有 New API Token。

官方用户指南列出的令牌可配置项包括：

- 独立额度与过期时间。
- 可调用模型范围。
- 所属分组及 Auto 分组顺序。
- 跨分组重试等路由相关选项。
- IP 白名单。
- 启用、禁用和删除。

权限链路可理解为：

```text
用户身份/角色 -> 用户分组 -> Token 限制 -> 模型权限 -> 可用渠道
```

推荐按应用和环境分别发放 Token，采用最小权限、设置有效期和额度，不要在前端代码、公开仓库或日志中暴露长期 Token。

## 7. 额度、计费与成本管理

New API 提供面向平台运营的用量和账务能力；具体计费规则由实例管理员配置，不能将平台显示金额直接等同于上游账单。

常见管理项包括：

- 用户或 Token 的额度、余额和使用量。
- 模型定价、模型倍率、分组倍率和渠道相关计费设置。
- 订阅套餐、兑换码、钱包和充值等用户侧功能（是否开放由实例配置决定）。
- 企业内部成本核算、部门成本分摊或企业客户账务管理。
- 对部分支持缓存计费的渠道配置缓存命中价格/倍率。
- 通过日志、统计和看板核对 Token、调用量及成本。

建议管理员：

1. 核实模型输入/输出价格、缓存价格和倍率配置。
2. 验证流式、非流式、失败、取消和重试请求的结算逻辑。
3. 区分上游真实账单、平台内部成本价和面向用户的结算价。
4. 定期对账，并为异常高消费设置告警或限额。

## 8. 日志、审计与数据看板

### 8.1 调用日志

用户可按权限查看自己的调用日志；管理员可查看全站 API 调用日志和用户操作记录。日志通常可帮助排查：

- 谁、何时调用了哪个模型。
- 请求成功、失败或被限流的状态。
- Token 用量、耗时、错误和计费结果。
- 调用经过的渠道/分流信息（视版本和日志字段而定）。
- 图像或异步任务等特定功能对应的任务状态和结果。

### 8.2 数据看板

控制台可提供模型调用分析、分流分析、用户分析、用量和性能健康等数据。不同角色可见范围不同，部分全局统计仅管理员或 Root 可见。

### 8.3 日志安全

- 将日志访问权限限制给必要人员。
- 避免保存不必要的完整 Prompt、响应和个人敏感信息。
- 确认错误日志是否会包含请求片段、上游地址或凭据信息，并按部署版本检查脱敏行为。
- 设置日志保留、备份和删除策略。

## 9. 用户、角色与控制台

官方功能指南将控制台角色概括为：

- **普通用户**：使用游乐场、个人 API 密钥、日志、钱包/订阅、个人资料等开放功能。
- **Admin**：在授权范围内管理渠道、模型、用户、兑换码、订阅等资源；管理员权限可进一步细分。
- **Root**：管理全局系统设置和完整权限。

具体菜单与功能可由 Root 的站点、品牌和系统设置控制。建议 Root 账号启用强认证、限制管理入口网络范围，并为 Admin 设置职责所需的最小权限。

## 10. API 与模型能力

New API 提供 AI 模型接口和管理接口两类 API。官方文档列出的常见模型接口包括：

- OpenAI 风格 Chat Completions、传统 Completions、模型列表。
- Responses API 和 Claude Messages。
- Gemini 原生/兼容模型调用。
- Embeddings、Rerank、内容审核。
- 图像生成/编辑、音频转写/翻译/语音合成、Realtime。
- 视频或其他异步任务能力（取决于渠道、插件和版本）。

管理 API 涵盖系统、认证、用户、渠道、模型、Token、兑换码、支付、日志、统计、任务、分组和供应商等。使用管理接口时应使用受控的管理员身份，不要把管理凭据交给普通业务客户端。

## 11. 部署与运维关注点

New API 官方文档将文档划分为安装部署、使用指南、API 参考、AI 应用、Skills、插件和帮助支持等部分。部署形态、数据库选项和环境变量应以对应版本的安装部署文档为准；不要把某一旧版本的配置直接当作当前版本规范。

上线检查：

- 固定并记录镜像/程序版本，阅读升级说明，先在测试环境升级。
- 备份数据库与配置，并验证恢复流程。
- 仅通过安全的密钥管理方式保存上游 API Key。
- 对公网入口配置 TLS、访问控制、速率限制和滥用防护。
- 隔离 Root/Admin 管理入口，启用强密码、2FA/Passkey 等可用安全机制。
- 监控服务健康、数据库、渠道失败率、延迟、成本和额度消耗。
- 对关键渠道做连通性测试、限流测试和故障切换演练。
- 评估日志中的敏感数据、留存期限及审计需求。

## 12. 许可证与合规

项目介绍说明 New API 采用 GNU AGPLv3。官方文档特别提示：如果修改项目并作为网络服务（例如 SaaS）部署，需要关注 AGPLv3 对完整源代码提供的要求；组织若无法接受相关义务，应先进行开源合规评估并咨询项目方商业授权选项。

合规使用要求包括：

- 合法取得上游 API Key、账号和服务授权。
- 遵守模型提供方服务条款、平台规则和适用法律法规。
- 若面向公众提供生成式 AI 服务，应自行评估备案、内容安全、身份管理、日志留存、税务、支付和消费者保护等义务。
- 网关本身不自动替代上游服务授权、内容安全治理或法定义务。

## 13. 适用场景与选型侧重

适合：

- 想要一个带 Web 控制台的自托管模型 API 统一入口。
- 需要集中管理上游渠道、模型、用户、Token 和分组。
- 需要内部成本核算、用量分析、订阅/额度管理。
- 业务客户端希望沿用兼容 API，而由平台调整上游渠道。

需要额外评估：

- 是否需要复杂的企业 IAM、审计集成、策略引擎或严格数据驻留控制。
- 对多租户隔离、可用性、横向扩展和灾备的具体要求。
- 上游接口的授权与再分发条款。
- AGPLv3 对修改、网络服务和产品集成的影响。

## 14. 一句话总结

> New API 是面向自用、团队和企业私有化场景的 AI API 网关与用量管理系统：通过统一 API 接入授权模型渠道，并用渠道路由、用户/Token 权限、额度计费、日志和数据看板完成集中管理。
