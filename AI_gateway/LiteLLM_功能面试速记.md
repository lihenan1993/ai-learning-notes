# LiteLLM 功能面试速记

## 一、LiteLLM 是什么

LiteLLM 是一个统一接入和治理大模型的组件，提供 Python SDK 和独立运行的 LiteLLM Proxy。SDK 供应用直接调用，Proxy 作为网关对外提供统一接口，并集中管理模型、访问权限、流量和成本。

从宏观上看，它把业务应用与不同模型供应商之间的接入差异和治理能力集中到一层，同时提供 MCP Gateway 和 Agent Gateway 能力。

## 二、主要功能

### 1. 统一模型接入

- **统一接口**：通过 OpenAI 兼容接口调用多个模型供应商及兼容服务。
- **协议和参数适配**：处理不同供应商的请求、响应、参数和流式输出差异。
- **多种模型能力**：统一接入文本生成、Embedding、图像、音频等能力；实际支持范围取决于模型和供应商。
- **模型组和别名**：将多个上游部署映射为业务使用的逻辑模型名称，隐藏具体部署细节。

### 2. 流量路由与容错

- **候选部署过滤**：结合模型组、权限、标签、地域、部署状态等条件确定可用上游，具体行为取决于配置。
- **路由和负载均衡**：在候选部署中按随机、用量、延迟、成本等策略选择上游，也可配置部署优先级。
- **重试与故障切换**：对符合条件的失败请求进行重试，或通过 Fallback 切换到备用部署或模型组。
- **限流与冷却**：管理请求速率，并在部署出现错误或限流时按配置暂时将其移出候选范围。

### 3. 身份、权限与安全

- **Virtual Key**：为应用、用户或团队提供网关侧访问凭证，将业务凭证与上游供应商密钥分离。
- **访问控制**：按 Key、用户或团队管理可访问的模型和资源。
- **安全治理**：支持结合 Guardrails、内容过滤和敏感信息处理等机制，对请求或响应实施安全策略。

### 4. 用量与成本治理

- **预算管理**：按 Key、用户或团队等维度设置预算及使用限制。
- **用量统计**：记录请求量、Token 使用量和模型调用情况。
- **成本统计与归因**：根据模型定价计算调用成本，并关联调用方、团队或 Key。

### 5. 日志、追踪与运维

- **请求日志**：记录调用状态、错误、延迟、模型、Token 和调用归属等信息；请求和响应内容的记录取决于配置。
- **可观测性集成**：对接日志、指标和追踪平台，例如 Prometheus、Langfuse 和 OpenTelemetry。
- **缓存**：缓存符合配置条件的请求结果，减少重复调用。
- **管理界面与 API**：管理模型配置、Key、用户、团队、预算和日志等网关资源。
- **扩展能力**：通过回调、插件和自定义逻辑扩展网关行为。

### 6. MCP Gateway

MCP Gateway 负责统一接入和管理 MCP Server，使客户端可以通过网关发现和调用 MCP 工具，并访问相应的资源与提示词。它提供认证、授权和访问治理；具体业务逻辑仍由 MCP Server 执行。

### 7. Agent Gateway

Agent Gateway 负责注册和代理 Agent，提供统一调用入口、认证授权、日志和成本追踪等能力，并支持 A2A 等 Agent 接入方式。Agent 内部的规划、状态管理和业务执行仍由对应的 Agent Runtime 负责。

## 三、整体关系

```text
业务应用 / Agent / 客户端
           |
           v
       LiteLLM Proxy
  |            |             |
模型网关    MCP Gateway    Agent Gateway
  |            |             |
模型服务    MCP Server      Agent 服务
```

其中，模型网关管理模型调用；MCP Gateway 管理工具等 MCP 能力的接入；Agent Gateway 管理 Agent 的接入和调用。三者都围绕统一入口和集中治理展开。

## 四、面试复述

> LiteLLM 是一个统一的大模型调用层，既有 Python SDK，也有独立部署的 Proxy。它通过兼容接口屏蔽不同模型供应商的调用差异，并提供模型路由、负载均衡、重试和故障切换。在治理方面，它支持虚拟 Key、权限控制、限流、预算、用量与成本统计，以及日志和可观测性集成。此外，它还提供 MCP Gateway 和 Agent Gateway，分别用于统一接入和管理 MCP 工具及 Agent 服务。
