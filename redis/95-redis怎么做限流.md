# Redis 怎么做限流

**限流是一段时间内一份共享配额**

广告里常见两档：创意对用户的日频控 `rl:freq:user:1001:creative:10086`，一天最多曝光三次，按自然日切窗口即可；广告主开放接口 `rl:api:adv:1001`，每秒一百次、允许短突发，才用令牌桶。

| | 窗口 / 节奏 | 允不允许突发 | 边界准不准 | Redis 怎么落 |
|---|---|---|---|---|
| **计数器（固定窗口）** | 一分钟、一天切一块，块内 `INCR` | 窗口开头能打满配额 | 交界处可能连放两块 | `INCR` + `EXPIRE` |
| **滑动窗口** | 以现在为终点往回看一段 | 取决于写法 | 日志准；计数是近似 | ZSet 记请求，或两块计数加权 |
| **令牌桶** | 匀速往桶里放令牌 | 允许，桶满就能一波打出去 | 不按自然窗口切 | Hash 记余量和上次补令牌时间 |
| **漏桶** | 匀速往外漏 | 出口匀速；突发被队列吃掉或直接拒 | 不按自然窗口切 | List 排队漏出，或记下次可漏时间 |

---

## 默认路径是固定窗口计数器

**配额按自然周期切、能接受窗口交界多放一点，用 `INCR` + `EXPIRE`。一天看三次、一分钟一百次，先说这个。交界处的双倍突发不能忍，再升滑动窗口。要允许短突发、平时按速率补额度，用令牌桶。下游只能匀速吃、多了必须排队或拒绝，用漏桶。不要一上来 ZSet 或令牌桶。**

固定窗口的实现就是一个带过期的计数器。key 带上窗口编号，过期当安全带：

```
INCR rl:freq:user:1001:creative:10086:20260313
        ↓
第一条才 EXPIRE 86400
        ↓
返回值 ≤ 3  → 放行
返回值 > 3  → 拒绝
```

`INCR` 和 `EXPIRE` 必须放进同一段 Lua。先加再设过期，中间进程挂了，这个 key 没有 TTL，计数器永远不归零，等于限流失效。事务入队时看不到中间结果，做不了「加完是 1 才设过期」，见 `75-pipeline事务和lua.md`、`70-redis事务.md`。

时钟以 Redis 为准。Lua 里用 `TIME`，不要用各实例自己的墙钟，机器时间不一致，窗口会对不齐。

```
请求进来
        ↓
EVAL：INCR；若为 1 则 EXPIRE
        ↓
n ≤ 配额  放行
n > 配额  拒绝
```

代价是**窗口边界**：23:59:59 放满 100，00:00:01 新窗口又放 100，两百毫秒里出去 200。按自然日的频控通常能接受，因为业务本意就是「今天三次」。按一秒、一分钟切的接口配额，交界处等于瞬间双倍，挡不住尖峰。

集群里一个限流维度就是一个 key，落在一个槽上。不要把所有用户塞进同一个 ZSet。要带哈希标签时写成 `{user:1001}:rl`，只为多 key 同槽，不是默认就要拆。热接口的限流 key 本身也可能变成热 key，见 `65-redis热key.md`。

## 滑动窗口：两种，别混成一种

面试说「滑动窗口」时，先问他要的是日志还是两块计数加权。前者准、贵；后者便宜、近似。

### 滑动日志：ZSet 记下每一次

成员是一次请求，分值是时间戳。每次先摘掉窗口外的，再看还剩几条，没超再 `ZADD` 自己。整段进 Lua。ZSet 的区间删除和计数见 `45-排行榜和延时队列.md`。

```
now = Redis TIME
        ↓
ZREMRANGEBYSCORE rl:login:user:1001 0 (now - 600000)
        ↓
ZCARD
        ↓
已满     拒绝
未满     ZADD rl:login:user:1001 now <req_id>
```

登录十分钟内五次、短信验证码一小时三条，要的就是「任意连续一段都不超」，固定窗口交界会漏。日志能答这个。

代价是内存跟请求次数走。一万 QPS 记一分钟，就是六万个成员，一个 key 上的大 ZSet，摘旧和计数都会打主线程，见 `60-redis为什么不能存大key.md`。成员用请求号，不要用毫秒时间戳当成员——同一毫秒两条会互相覆盖。key 仍要设 TTL，避免没人访问时残骸常驻。

### 滑动计数：两块固定窗口做加权

只存当前窗口和上一窗口两个计数。估计值 = 上一块 ×（这块还没走完的比例）+ 当前块。比日志省内存，比固定窗口少一点交界双倍，仍是近似，不是精确的「任意连续 60 秒」。高 QPS 接口从固定窗口升级，先到这一档，不必直接上 ZSet。

```
上一窗口 80 次，当前已过 30%，当前窗口 20 次
        ↓
估计 = 80 × 0.7 + 20 = 76
```

## 令牌桶：匀速补，允许把桶打空

桶有容量，令牌按固定速率往里放，放满不再加。一次请求拿走一个（或几个）令牌；不够就拒。空闲时令牌攒着，到来之后可以在容量以内一次性打出去。

广告主接口平时每秒补 100 个令牌，桶容量 200：正常是每秒 100；停两秒再来，最多连打 200，再往后必须等补。短点几下能过，持续打满会被按住。这是令牌桶要的形状。

Redis 里用 Hash 记余量和上次补令牌的毫秒时间，请求到来时按间隔把该补的补上，再决定扣不扣。补多少、扣不扣，都依赖读到的余量，必须 Lua。

```
HGET tokens / last_ms
        ↓
按 (now - last_ms) × 速率 补令牌，封顶容量
        ↓
余量够   扣掉，写回 Hash，放行
余量不够 写回补完后的余量，拒绝
```

不要每个令牌当一个 List 元素真往里 `LPUSH`。容量和大速率下那是在造大 key，而且补令牌本身要另写循环。Hash 两个字段就够。

令牌桶不消除下游压力，它只是允许合法突发。下游是计费、写库，吃不下一波 200，用漏桶，不要用令牌桶。

## 漏桶：管出口，不是再做一个令牌桶

令牌桶控制谁能进：桶里有令牌就能进，下游会看到突发。漏桶控制怎么出：进来的先进入桶，按固定速率漏给下游。下游看到的是匀速；桶满了才溢出拒绝。突发变成排队延迟，或变成拒绝，取决于桶还有没有空位。

点击回调打计费 `leak:callback:billing`，计费每秒只能吃 500 条。漏桶让出口钉在 500，多来的进队；队满了接口直接 429，而不是把计费打穿。

实现不要和令牌桶共用同一套「余量加减」却宣称更平滑。余量模型在桶空时照样能一波打满容量，下游仍然看到突发。漏桶要的是出口时钟：

```
请求到达
        ↓
桶满（LLEN ≥ 容量）  拒绝
未满                 LPUSH leak:callback:billing
        ↓
另一头按固定间隔取出，交给计费
```

只要「现在过不过」，不必真排队时，记下次可漏时间：到点才放行，提前更新下一次。形状仍是匀速放行，拒绝来得更快，用户少等，下游仍然看不到尖峰。

漏桶的代价是延迟。队一长，请求在 Redis 里堆着，和当队列一样要裁，见 `85-redis能当消息队列吗.md`。不要指望漏桶顺便做成带 ACK 的可靠投递。

| | 令牌桶 | 漏桶 |
|---|---|---|
| **管哪一头** | 入口有没有额度 | 出口漏多快 |
| **下游看到什么** | 可以一波突发 | 匀速；突发在桶里或被拒 |
| **空闲之后** | 令牌攒满，允许打空 | 桶空了，仍按漏速往外走 |
| **适合** | 开放接口、短抖动要过 | 保护写库、保护第三方 |

## 为什么必须 Lua，以及限流本身也会打 Redis

限流是「读当前进度，再决定写不写」。`INCR` 之后看是不是第一才 `EXPIRE`，ZSet 先数再加，令牌桶先补再扣，拆开都会在中间被别的实例插进一次，配额就被多放。Pipeline 不防插队；事务看不见中间结果。见 `75-pipeline事务和lua.md`。

脚本要短。每个请求一次 `EVAL`，脚本里不要扫大 key、不要循环补一千个令牌。Lua 过长会堵主线程，见 `20-redis单线程模型.md`。

实例多、配额紧时，每个请求都问 Redis，限流会先把 Redis 打满。先在进程里放一只较小的本地令牌桶挡住明显超标的，不确定再问 Redis。本地各自一份，总和会略松；要的是少打 Redis，不是替代那份共享配额。网关限流是另一层，挡的是单机或入口，挡不住「十个实例各放 100」。雪崩时入口限流和这里是同一类手段，见 `110-缓存击穿穿透雪崩.md`。

限流只挡流量。库存超卖要原子扣减，不是把 QPS 压低就正确，见 `125-秒杀怎么防超卖.md`。

## 对照记

```
固定窗口 INCR+EXPIRE    最轻；交界可双倍
滑动计数（两块加权）    仍两个整数；近似抹交界
滑动日志 ZSet           任意窗口准；内存跟次数走
令牌桶 Hash+Lua         匀速补，允许把桶打空
漏桶 队列 / 下次可漏     出口匀速；突发变延迟或拒绝
本地桶 + Redis          少打 Redis；本地偏松
网关限流                挡入口 / 单机，不是集群共享配额
```

```
INCR 和 EXPIRE 拆开     key 可能永不过期
客户端墙钟              各实例窗口错位
滑动日志一个大 ZSet     大 key，摘旧堵主线程
令牌桶当真 List 存令牌  无必要的大 key
余量模型当漏桶          下游仍可能看到突发
用事务做先读再写        入队时看不到计数
```

一句话：**自然周期配额用固定窗口；要任意一段都不超，用滑动窗口。允许短突发用令牌桶，要出口匀速用漏桶。先读再决定必须 Lua；限流是配额，不是锁，也防不住超卖。**
